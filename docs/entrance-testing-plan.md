# План: входное тестирование (лечение холодного старта)

> Backlog-файл. Фича откладывается сознательно: сначала стабилизируем подбор уроков и ДЗ.
> Цель — у нового ученика ещё до первого урока появляется начальный уровень, и ИИ-подбор
> не гадает на пустом досье.

## Идея

Для каждого класса (5–11) мы заранее составляем **входное тестирование** и храним его в базе.
Новый ученик проходит тест, проверка автоматическая, результат превращается в стартовое досье:
`StudentProfile.levelScore`, стартовая карта тем и статусы по номерам теста. Дальше обычный
конвейер подбора работает как с «тёплым» учеником.

## Что уже готово в базе (использовать, не создавать заново)

- Модели `Test` (kind `PLACEMENT`, `grade` через тему/поле), `TestQuestion`, `TestAttempt`,
  `TestAnswer` — таблицы созданы миграцией `add_lessons_and_groups`, кода под них нет.
- `TopicHomeworkNumber.usableInDiagnostic` — флаг «номер годится для диагностики».
- `TopicHomeworkNumber.answerLatex` — эталонный ответ для автопроверки вводом.
- `StudentProfile.levelScore`, `placedAt` — куда кладётся результат.
- `Topic.grade` / `Topic.subject` — привязка тем к классу.

## Функции, которые нужно добавить

### 1. Составление теста (учитель/разработчик)

- `createEntranceTestAction` — создать тест для класса: `grade`, `title`, набор вопросов из
  банка (`homeworkNumberId` + `points`, порядок) либо кастомный `promptLatex`/`correctAnswer`.
- UI: страница `/teacher/entrance-tests` — список тестов по классам, редактор состава
  (переиспользовать выбор номеров из доски выдачи ДЗ; фильтр по `usableInDiagnostic`).
- Пометка номеров флагом `usableInDiagnostic` в редакторе темы (рядом с сложностью).

### 2. Прохождение теста (ученик)

- Назначение: при создании ученика с указанием класса тест назначается автоматически;
  плюс кнопка «Назначить входной тест» на странице ученика.
- UI ученика `/student/entrance-test`: вопросы по одному, условие рендерится KaTeX,
  ответ вводится текстом/числом; таймер по `durationMinutes`; `TestAttempt` со статусами
  `IN_PROGRESS → SUBMITTED`.
- Баннер на дашборде ученика, пока тест не пройден.

### 3. Автопроверка

- `gradeEntranceTestAttempt(attemptId)` — сверка ответа с `correctAnswer`/`answerLatex`:
  нормализация (пробелы, запятая/точка, эквивалентные формы типа `0.5` и `1/2`);
  спорные случаи можно добивать существующим ИИ-конвейером (тот же `getAiCheckConfig`),
  но базовая сверка — чистый код, без модели.
- Результат: `TestAttempt.score/maxScore`, `TestAnswer.isCorrect/awardedPoints`.

### 4. Превращение результата в стартовое досье

- `applyPlacementResult(studentId, attemptId)`:
  - `StudentProfile.levelScore` (0–100) + `placedAt`;
  - по вопросам из банка проставить `StudentTopicNumberStatus` (верно → GREEN, неверно → RED) —
    карта тем и досье наполняются сразу;
  - `TopicMastery` по темам теста (порог, например ≥70% → mastered).

### 5. Интеграция с ИИ-подбором

- В `getLessonPlanContext`: если истории проверок нет, но есть `levelScore`/результат теста —
  передавать в досье блок `placement: { levelScore, testedAt, weakTopics, strongTopics }`.
- В промптах уроков и ДЗ — ветка: «истории мало, опирайся на placement».

### 6. Сервисное

- Отчёт учителю: страница результата теста (по вопросам, по темам).
- Дев-панель: счётчик пройденных тестов; действие «переназначить тест».
- Тесты: нормализация ответов, подсчёт баллов, applyPlacementResult (чистые функции).

## Порядок внедрения (когда возьмёмся)

1. Миграций не нужно (всё есть) → сразу actions + читалки.
2. Редактор теста → прохождение → автопроверка → applyPlacementResult → интеграция в досье.
