# Промпт: пункты условия растягивают карточку вместо переноса

## Симптом

Длинное условие с пунктами («а)», «б)», «1)») не переносится по строкам — вместо этого **растягивается сама карточка**, ломая сетку.

## Причина

Это не проблема переноса текста, а проблема расчёта ширины контейнера. Элементы flex и grid по умолчанию имеют `min-width: auto`, то есть **не могут стать уже своего содержимого**. Пока хоть один предок в цепочке не получит `min-width: 0`, браузер будет расширять карточку под самый широкий неразрывный кусок, и никакие `max-w-full` / `overflow-wrap` внутри не сработают — `max-width: 100%` считается от родителя, который сам растянулся по контенту.

Основной подозреваемый — `components/teacher-topic-view-numbers.tsx:25`: `<div className="grid gap-3 xl:grid-cols-2">`, где `<article>` — grid-элемент без `min-w-0`. Аналогичные цепочки проверь в `student-single-number-card.tsx`, `teacher-single-number-card.tsx`, `topic-answer-manager.tsx` и на `/teacher/topics/[topicId]/numbers/[number]`.

## Что сделать

**1. Пройди цепочку предков от `LatexAnswerPreview` вверх до карточки** и на каждом flex/grid-элементе поставь `min-w-0` (для колонок в flex-col — ещё и `min-h-0` не нужен, только ширина). Начни с `<article className="teacher-number-card …">` — добавь `min-w-0`, и на сам грид-контейнер тоже.

**2. В `components/latex-answer-preview.tsx`** корневому контейнеру превью (строка ~87) добавь `min-w-0 max-w-full`, и то же самое обёртке display-формулы (~строка 97), заодно убрав с неё `overflow-x-auto`.

**3. Разреши перенос внутри KaTeX.** `katex.min.css` (импорт в `app/layout.tsx`) ставит `white-space: nowrap`, из-за чего формула остаётся одним неразрывным куском и задаёт минимальную ширину карточки. Добавь в `app/globals.css` после подключения темы:

```css
.katex { white-space: normal; }
.katex .base { white-space: nowrap; }   /* дробь и корень не рвутся посередине */
.katex-display > .katex { white-space: normal; text-align: left; }
```

**4. Проверь, что механика пунктов вообще включается.** В `splitLineIntoItems` регулярка `/^(?:[А-ЯЁA-Z]|\d{1,2})\)/` ловит только прописные буквы со скобкой — строчные (`а)`, `b)`) и точку (`а.`, `1.`) не видит. Расширь её на обе раскладки, оба регистра и оба разделителя. Условие `boundaries.length < 2` тоже неверное: единственный пункт должен оставаться неразрывным блоком. Логику разбиения вынеси в чистую функцию и покрой тестами в `tests/` (стиль `tests/number-tagging.test.ts`): скобка и точка, оба регистра, кириллица и латиница, единственный пункт, метка внутри `$…$` — не метка.

## Проверить

- Карточка номера **не шире своей колонки** ни на одном экране; сетка `xl:grid-cols-2` не разъезжается.
- Пункт целиком уходит на следующую строку, а не разрезается посередине.
- Узкий экран 360 px: страница не скроллится вбок.
- Короткие условия и inline-математика внутри текста выглядят как раньше.
- `npm run lint` и `npm run test` зелёные.

Копия по-русски, цвета только через существующие CSS-переменные.
