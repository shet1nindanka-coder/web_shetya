## Порядок выполнения

Последовательный. Пять планов правят `app/globals.css`, параллельный запуск даст конфликты.

```
005 → 006 → 007 → 008 → 009 → 010 → 011 → 012 → 013
```

Жёстких зависимостей между планами партии 2 нет — порядок выбран по убыванию важности,
чтобы при остановке на середине сделанным оказалось самое ценное. Все они опираются на
токены `--duration-*`, введённые планом 001, и на класс `.shbz-dropdown-panel`,
созданный планом 004.

Отдельно про 007: находки «шиммер через `background-position`» и «шиммер календаря
недостижим для reduced-motion» объединены в один план намеренно — обе завязаны на общий
keyframe `ui-shimmer`, и разделить их на два коммита нельзя.

## Что осталось за рамками

- **Анимация закрытия оверлеев.** Планы 004, 005 и 006 анимируют только появление.
  Закрытие остаётся мгновенным: анимация выхода требует держать элемент смонтированным
  после закрытия и вести отдельное состояние — это изменение логики компонентов, а не
  их движения.
- **Перевод streak-анимаций с keyframes на переходы.** План 012 чинит только пропущенный
  повторный запуск; полная переделка ради события, случающегося раз в сутки, не окупается.
- **Появление вердикта автопроверки** (`components/student-homework-check.tsx:169`) —
  единственная «упущенная возможность» из аудита: после нескольких секунд ожидания блок
  с результатами возникает без анимации. Это добавление нового движения, а не исправление
  существующего, поэтому в набор не вошло.
- **`components/telegram-spoiler.tsx`** — содержит вбитую вручную кривую и rAF-цикл без
  учёта reduced-motion, но компонент нигде не импортируется. Мёртвый код не трогаем.
- **Мёртвые `.mobile-overlay` / `.mobile-panel`** (`app/globals.css:1615`, `:1618`) —
  0 использований. План 011 оживляет `.ui-stagger-*`, но эти две оставлены как есть:
  они относятся к мобильному меню и требуют отдельного решения.
