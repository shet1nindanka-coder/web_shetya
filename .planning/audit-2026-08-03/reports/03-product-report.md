## 0. Как поднимался стенд (и что это значит для достоверности)

Стенд собран не на Маке разработчика, а в изолированном облачном контейнере — там есть `psql`,
возможность гасить БД, сеять объём, гонять headless-браузер и подменять ИИ-провайдера.

| Компонент | Как поднят | Отклонение от боевого |
|---|---|---|
| PostgreSQL 16 | нативно, порт 5433, схема — **все 22 миграции применены по одной** | нет |
| Приложение | `npm run dev` (Next.js 15.5.14), `.env` как в `.env.example` + `TZ=Europe/Moscow` | dev-режим: первая загрузка маршрута компилируется 1–6 с, эти цифры в отчёте не используются как замеры |
| Prisma | из песочницы недоступен `binaries.prisma.sh`, поэтому клиент работает через официальный **pg-адаптер + WASM-движок**; патч только в `node_modules`, **исходники проекта не тронуты** | другой движок исполнения запросов; SQL и коды ошибок Prisma те же (P2021/P2022/P2002 воспроизводились штатно) |
| Миграции | применены `psql`-ом по одной вместо `prisma migrate deploy` (нет schema-engine) | эквивалентно: применён ровно тот SQL, что лежит в репозитории — **это и вскрыло находку PROD-003** |
| ИИ-провайдер | локальный мок вместо ProxyAPI, режимы: ok / низкая уверенность / инъекция / мусор / пустой ответ / 401 / 429 / 500 / 20 с задержки | **ни одного платного вызова**; качество вердиктов реальной модели не проверялось (см. §8) |
| Браузер | системный Chromium через Playwright, десктоп 1400×950 и мобильные 375×667 / 390×844 | вместо Chrome пользователя |
| Данные | штатный `npm run db:seed`, поверх — посев объёма: 50 тем × 40 номеров, 10 учеников, ~800 статусов на ученика, 120 ДЗ, полгода истории | — |

Единственный файл, записанный в папку проекта: `.planning/audit-2026-08-03/assets/_src-for-audit.tgz`
(архив исходников для переноса в контейнер). Удалить его нужно вручную.

## 1. Резюме для владельца

**Готов ли продукт к пилоту с реальным 11-м классом в сентябре: да, но не в текущем виде — сначала нужно закрыть два сценария потери данных и один сценарий блокировки ученика.**

Продукт заметно лучше, чем «MVP на скорую руку»: сквозной путь «учитель выдал ДЗ → ученик прислал фото →
ИИ проверил → статусы обновились → учитель видит вердикты → PDF-отчёт» проходит целиком и без падений;
интерфейс аккуратный, тексты русские, пустые состояния написаны по-человечески; защита от двойных кликов,
дублей ДЗ и подделки статуса учеником реально работает; импорт номеров ведёт себя ровно как заявлено
(preview ничего не пишет в базу). Это уже можно показывать.

Семь главных выводов:

1. **Две операции безвозвратно уничтожают работу ученика без честного предупреждения.** «Отменить ДЗ»
   удаляет присланные фото решений и всю историю ИИ-проверок (диалог обещает снять только дедлайны).
   Замена набора номеров в теме молча стирает прогресс, заметки, LaTeX-условия и ответы по исчезнувшим
   номерам — у всех учеников сразу, без подтверждения вообще. Проверено вживую, с фиксацией «до/после» в БД.
2. **Перезапуск приложения посреди ИИ-проверки блокирует ученика на 45 минут.** Проверка навсегда остаётся
   в статусе CHECKING, ученик видит «обычно это занимает до минуты», кнопка повтора отвечает
   «Проверка уже идёт». Учитывая, что деплой — это `pm2 restart`, в первые недели пилота это будет случаться
   регулярно.
3. **Миграции в репозитории не создают таблицу `Notification`.** На чистой базе, поднятой документированным
   способом (`prisma migrate deploy`), уведомления не работают вовсе, а каждый заход ученика пишет ошибку
   Prisma в лог. Значит, боевая база сейчас содержит объект, которого нет в истории миграций — при переезде
   на новый сервер это выстрелит.
4. **Любой сбой БД (или любое исключение в layout) показывает пользователю английскую страницу**
   «Application error: a server-side exception has occurred… Digest: 1144446620» без навигации и без
   объяснения. Ученик 11 класса из этого не поймёт ничего.
5. **Главный ученический сценарий — фото с телефона — упирается в лимит 15 МБ на запрос.** Клиентского
   сжатия нет; одно фото современного телефона 8–9 МБ, поэтому уже две страницы решения разом дают ошибку,
   хотя подпись под кнопкой обещает «До 10 фото».
6. **Учитель — не главный пользователь текущего интерфейса.** Статистика и дев-панель доступны только роли
   DEVELOPER; у учителя в меню нет ни статистики, ни предурочного дашборда, ни работы с темами.
   По ТЗ (модуль M6) предурочный дашборд — обязательная часть MVP.
7. **Позиционирование «не ГДЗ» держится на одном клике.** Ученик может открыть `/student/numbers/<любой>`,
   раскрыть спойлер с эталонным ответом (даже если номер ему не выдавали), переписать его и получить от
   ИИ-проверки зелёный статус. Это осознанное решение под самопроверку, но в паре с автопроверкой оно
   позволяет получить незаслуженный зелёный без единой выкладки.

### Что сломается в первую неделю пилота

| Что | Почему именно на первой неделе |
|---|---|
| Зависшие ИИ-проверки после каждого деплоя | правки по горячим следам в сентябре неизбежны; каждый рестарт «съедает» проверки, идущие в этот момент |
| Ошибки при загрузке фото с телефонов | 30 учеников фотографируют по 2–4 страницы; лимит 15 МБ на запрос ловится сразу |
| Отменённые ДЗ вместе с фотографиями | «выдал не то, отменю и выдам заново» — самое естественное действие учителя в первые дни |
| Английская страница ошибки при любом чихе БД | одиночный инстанс, ручные миграции, отсутствие health-check |
| «Проверьте подключение к PostgreSQL» в лицо учителю | текст показывается в форме создания ученика — ровно в тот момент, когда учитель заводит класс |
| Пустые ИИ-подборы | пока банк задач не наполнен, подбор молча собирает 1 задачу на 60-минутный урок |

## 4. Находки

### PROD-001 — «Отменить ДЗ» безвозвратно удаляет фото решений и всю историю ИИ-проверок

- **Серьёзность:** BLOCKER (нельзя пускать пилот в таком виде)
- **Кого задевает:** ученика — теряется присланная работа; учителя — теряется доказательная база и диагностика ошибок, на которой строится ИИ-подбор
- **Уверенность:** воспроизведено вживую, с фиксацией состояния БД и файлового хранилища до и после
- **Где:** `/teacher/students/[studentId]`, кнопка «Отменить ДЗ» → `DELETE /api/teacher/homeworks`
  (`app/api/teacher/homeworks/route.ts:112-249`), текст диалога — `components/teacher-homework-review-list.tsx:271`

**Ожидаемое поведение.** Отмена выданного ДЗ снимает задание и дедлайны. Присланные учеником фотографии
и вердикты проверки — это его работа и история наблюдений за ним; их удаление, если оно вообще нужно,
должно быть названо в диалоге подтверждения прямым текстом.

**Фактическое поведение.** Диалог говорит: «ДЗ будет удалено, дедлайны будут сняты с его номеров.
Это действие нельзя отменить.» Фактически вместе с ДЗ удаляются: все `HomeworkSubmissionPhoto`,
все `HomeworkCheck` и `HomeworkCheckResult` (вердикты, распознанные ответы, комментарии, диагностика
`errorKind`/`errorNote`, пометки о подозрении на списывание и на инъекцию), а сами файлы физически
стираются из хранилища. Замеры до/после одной отмены:

```
до:     ДЗ 2 · фото 2 · проверок 1 · результатов 3 · файлов в хранилище 8
после:  ДЗ 1 · фото 0 · проверок 0 · результатов 0 · файлов в хранилище 6
```

Побочно: статусы, выставленные ИИ (301 → жёлтый, 302 → красный), после отмены остаются, а строка

**Шаги воспроизведения.**

5. Фото и вердикты исчезают безвозвратно; в хранилище файлов уже нет.

**Последствие.** Сентябрь, учитель выдал не ту тему, отменяет ДЗ, чтобы выдать заново — и стирает
работу, которую ученик уже сфотографировал и прислал. Восстановить нечем: ни корзины, ни архива нет.
Дополнительно обнуляется диагностика ошибок, на которой ИИ-подбор строит «досье» ученика.

**Оценка трудоёмкости:** S — в объёме честного текста диалога и решения «отвязывать, а не удалять».

### PROD-006 — Фото с телефона упирается в лимит 15 МБ на запрос

- **Кого задевает:** ученика

- **Где:** `/student/homeworks/[assignmentId]`, `app/api/student/homework-submissions/route.ts`

**Ожидаемое поведение.** Ученик выбирает 3–4 снимка страниц решения и отправляет их одним действием.

**Фактическое поведение.** Лимит считается по суммарному размеру одного запроса, а интерфейс
отправляет все выбранные файлы разом:

```
1 фото 8.7 МБ           → HTTP 200, 0.6 c
3 фото по 8.7 МБ (26 МБ) → HTTP 413 «Суммарный размер загрузки не должен превышать 15 МБ.»
```

Клиентского сжатия нет (в компоненте нет ни canvas, ни createImageBitmap) — сжатие происходит уже

и ни слова о мегабайтах. То есть обещание «10 фото» физически невыполнимо ни для одного современного
телефона: 2 снимка — это уже 16–18 МБ.

Приятная деталь, которую стоит сохранить: подмена типа ловится (PDF, переименованный в jpg, отвергается
сообщением «Тип файла не соответствует его расширению»), чужое ДЗ даёт 404.

**Шаги воспроизведения.**
1. Открыть `/student/homeworks/[id]` с телефона.
2. Выбрать 3 фотографии, сделанные камерой телефона (по 5–9 МБ).
3. Получить ошибку 413 вместо загрузки.

**Последствие.** Сентябрь, 30 учеников, у каждого решение на 2–4 листах: массовые «у меня не грузится».
Обходной путь (грузить по одному) в интерфейсе никак не подсказан.

**Оценка трудоёмкости:** M (сжатие на клиенте + честная подпись + загрузка по одному файлу).

## 8. Что осталось непроверенным и почему

1. **Качество реальной ИИ-модели.** Все вызовы шли в локальный мок (запрет на платные внешние API).
   Не проверено: адекватность вердиктов на настоящем рукописном решении, устойчивость к почерку,
   осмысленность подобранных задач, реальные тайминги ProxyAPI, поведение при частичном ответе модели.
   Промпты прочитаны — они подробные и с защитой от инъекций, но это оценка текста, а не поведения.
2. **Таймаут модели (180 с) и полная цепочка ретраев** — режим «модель не отвечает» запускался,
   но до конца 3×180 с не доводился.
3. **Тёмная тема** — все замеры контраста сделаны в светлой. В `globals.css` для тёмной темы заданы
   другие значения, они могут быть и лучше, и хуже.
4. **Реальный скринридер** (NVDA/VoiceOver/TalkBack) не запускался — проверялась только разметка.
5. **Реальные мобильные браузеры и камера телефона.** Эмуляция Chromium не покрывает выбор
   «Сделать фото», ориентацию EXIF на настоящем снимке, поведение клавиатуры iOS.
6. **Хранилища S3 и Vercel Blob** — стенд работал на локальном диске; переключение бэкендов
   и доживаемость старых ссылок не проверялись.

## 9. Замечено вне зоны ответственности (для агента по безопасности)

Одной строкой, без разбора — это чужая зона:

- `GET /api/student/homeworks/find-number` и страница `/student/numbers/[N]` дают ученику условие
  и эталонный ответ **любого** номера банка, без проверки выдачи (см. PROD-008).
- `POST /api/student/topic-status` создаёт строку прогресса по любому номеру любой темы (PROD-025).
- При недоступной БД API отвечает `401 «Сессия истекла»` — состояние инфраструктуры маскируется
  под состояние аутентификации.
- В `HomeworkCheck.error` (и далее в интерфейс ученика) попадает текст ошибки внешнего провайдера
  без фильтрации (PROD-009).
