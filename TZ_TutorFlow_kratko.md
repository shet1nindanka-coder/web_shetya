# ТЗ (кратко). «Система помощи учителю с ИИ» — TutorFlow

**Дедлайн MVP:** 1 августа 2026 (демо для Сколково) · **Пилот:** 11 класс с сентября · **Дата:** 24.06.2026

**Суть.** Система помощи учителю по математике (далее — информатика). Каждый ученик идёт по своей траектории в своём темпе; учитель на уроке видит, к кому подойти и что разобрать; освоение тем засчитывается по тестам. Это не ГДЗ/решебник/учебник. Резидентство Сколково экономит ~3–4 млн ₽ — нужен показуемый MVP.

**Уже работает (база TutorFlow):** авторизация и роли; темы с файлами теории/ДЗ и нумерованными задачами; LaTeX-условия/ответы; статус-светофор по номерам + заметки + дедлайны (для каждого ученика); выгрузка в Excel; защищённая выдача файлов; SSE-реалтайм.

**Важно:** модели для всего нового (`Lesson`, `Test`, `TopicMastery`, `StudentProfile`, `prerequisites`…) уже есть в `prisma/schema.prisma`, но **не мигрированы и не реализованы**. Первый шаг разработки — миграция.

## Что строим (P0 — обязательно к 1 августа)

| Модуль | Что делает | Пр. | Статус |
|:-----|:--------------------------------------------------------|:-|:----|
| M0. Банк задач | Метаданные номеров: сложность, время решения, флаг диагностики, «важный номер»; массовое наполнение | P0 | поля есть |
| M1. Диагностика | Входной тест → уровень → стартовая точка траектории | P0 | новое |
| M2. Траектория | Последовательность тем с учётом иерархии (prerequisites); зачёт темы (TopicMastery) | P0 | новое |
| M3. Режим урока | Старт урока; очередь обхода (время входа + приоритет); персон. задание + PDF; «на разбор»; посещаемость | P0 | новое |
| M4. Тесты + зачёт | Массовая рассылка персональных тестов (15 мин), автопроверка → засчёт освоения темы | P0 | новое |
| M5. Дашборд учителя | Сводка перед уроком: сколько зелёных/жёлтых/красных, что «на разбор», приоритетные ученики | P0 | частично |
| M6. Самост. планы | План из банка между уроками с отсечкой по времени | P1 | частично |
| M7. Контент | Модельные решения/методички по ключевым типам (пределы, тексты, графики, параметры) | P1 | база есть |
| M8. Подбор (ИИ) | Движок «что дальше + состав теста»; на MVP — алгоритм, позиционируем как ИИ | P0 | новое |
| M9. Два предмета | Математика (пилот) + информатика (позже) | P1 | каркас |
| M10. Будущее | Антифрод/фото-проверка решений; контракты с родителями и штрафы за пропуски | P2 | после MVP |

## Дорожная карта (до 1 августа)

- **Спринт 1 (до ~8 июля):** миграция новых моделей; банк задач (M0); диагностика (M1).
- **Спринт 2 (до ~22 июля):** траектория и иерархия (M2); режим урока (M3); самостоятельные планы (M6).
- **Спринт 3 (до 1 августа):** тесты и автозачёт (M4); дашборд учителя (M5); алгоритм подбора (M8); методички (M7) → **срез MVP**.
- **Дальше:** сентябрь — мягкий запуск на 11 классе; октябрь — стабилизация; декабрь — добор 10 класса; затем M10.

**Стек:** Next.js 15 · React 19 · TypeScript · PostgreSQL + Prisma · Tailwind. Реалтайм/лимиты — in-memory (1 инстанс; при масштабе нужен внешний брокер). Нужны: 1–2 разработчика из преподов + группа на переработку ~100 задач (оригинальность контента).

## Открытые вопросы (решить на созвоне)

1. Убрать жёлтый статус (оставить зелёный/красный)?
2. Как отличать «честный красный» от «ленивого» (пометка ученика или эвристика)?
3. Очередь на уроке: только время входа или + приоритет (красные/дедлайны)?
4. Тесты — только автопроверяемые (число/короткий ответ) ради мгновенного зачёта?
5. Синхронизация в MVP — видео-лекции или методички?

## Критерии приёмки MVP (демо для Сколково)

Сквозной сценарий на тестовой группе: диагностика → персональный план → ученик решает и отмечает статусы → учитель видит дашборд → старт урока с очередью обхода и заданиями (PDF) → массовая рассылка персональных тестов → автозачёт тем → Excel-отчёт.
